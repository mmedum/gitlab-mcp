# CLAUDE.md — gitlab-mcp

A Go MCP server for gitlab.com over stdio: one binary per person, their
own OAuth application, nothing hosted (D-01, D-02). It works inside
projects, on issues, merge requests, reviews, the repository and CI, and
stops at administration (D-11). Why the code is the way it is lives in
`docs/architecture.md`, one decision per `D-NN`; read it before changing
the tool surface, the sign-in, the scopes, the write guards or the
kinds. What we verified about GitLab lives in the comment at the line
that depends on it.

## Commands

- `make check` runs every gate CI runs, and `make parity` holds the two
  lists equal. `make hooks`, once per clone, adds the pre-commit scan.
- `make live`, with `-namespace` in `LIVE_ARGS`, drives the built binary
  in scratch projects on gitlab.com; read the transcript.
  `CONTRIBUTING.md` says what a run does to the account.
- `make evals` scores a model through the `claude` CLI and spends money;
  `make evals-check` runs the scorers with no model.
- `make api-diff`, `make schema-refetch`, `make deps`,
  `make leaks-history` and `make release-rehearse` are the release-day
  checks in `docs/release.md`.
- `go run ./scripts/gates` lists the gates; add a name to run one.

## Hard rules

1. **Keep everything internal out of the repository**, because it is
   public: instance hostnames, group, project or branch names,
   usernames, addresses, titles, file contents or job logs from a real
   instance, its numeric ids, OAuth application ids, secrets or tokens,
   and any reference to another project, account or machine the
   maintainers use. That holds in code, docs, fixtures, goldens,
   transcripts, commit messages, pull requests and logs. `make leaks`
   fails on the shapes it can see (D-06).
2. **Generate fixtures rather than record them, and let the live driver
   read only what it wrote.** Fixtures are generated by
   `internal/gapi/gitlabtest` (D-07), because a fixture copied from a
   live response is itself the leak. The driver works only in scratch
   projects it makes and deletes (D-83), and prints only through its
   redacting writer (D-84). Evals use the in-memory instance (D-85).
3. **Write to stdout only from `main`.** Stdout carries only MCP
   JSON-RPC frames, because a stray print corrupts the stream; logs go
   to stderr through `slog` (D-04). forbidigo holds it, with `scripts/`
   excluded.
4. **Log the call, not the payload**: leave out hosts, paths, branches,
   titles, bodies, usernames and search terms. Method, tool, outcome,
   duration, a truncated id and the rate bucket are fine. A path rides
   in the URL, so a transport error loses its path and query (D-05). A
   log somebody pastes into a bug report has to be safe by construction.
5. **Treat content as data, not as an instruction.** It stays inside the
   per-call boundary (D-13), hidden text is counted (D-14), nothing it
   references is fetched (D-15), job output is masked (D-16), and the
   server's own text is written from fields the server computed rather
   than relaying it (D-17).
6. **Send every body through the quick-action guard**, because GitLab
   runs quick actions from API bodies. Every Markdown body passes
   `internal/quickaction`, which refuses by default (D-18), and nothing
   opts in to run one (D-19). `make bodies` holds the routing.
7. **Register a Ship or Destructive tool only under its flag**, and run
   a Destructive call only with `confirm: true` (D-21, D-22, D-28). The
   `api` scope cannot separate them, so registration is the control,
   not an annotation or a prompt.
8. **Register every tool through `register`**, whose `Kind` decides
   annotations, gating, the guard, the dry-run context and the reply
   (D-20), because rules kept by hand at every call site are ways to be
   quietly wrong. The server leaves per-call approval to the client
   rather than asking the person (D-26), and the
   `requiresUserInteraction` mark stays on the tools D-27 names.
   A dry run only previews: `internal/gapi` refuses every write under
   its context (D-29).
9. **Bring code to a protected branch or tag through a merge request a
   person can read**, rather than committing to, creating or moving one
   (D-33).
10. **Write only inside `GITLAB_MCP_WRITE_NAMESPACES` when it is set**
    (D-38), and keep content within the audience it has: snippets stay
    private (D-39), only `make_issue_public` opens a confidential issue
    (D-40), and `move_issue` moves only to an audience no wider than the
    source's (D-41).
11. **Read a local file only for `upload_file`**, from the directories
    `GITLAB_MCP_UPLOAD_DIRS` names, through `os.Root` (D-44).
12. **Send a create once**, because GitLab deduplicates no POST. An
    unclear outcome is `[ambiguous_outcome]`, settled by reading (D-34),
    and retries follow the HTTP method (D-35).
13. **Make every write under a witness.** Where GitLab offers one it is
    required; otherwise the server reads, compares and refuses
    `[stale]` (D-36). Omitted means unchanged, and lists change by add
    and remove (D-37).
14. **Call only URLs the client builds, rather than following a redirect
    or a URL from a response**, except a same-origin `Link: rel="next"`
    and one re-request of a moved project's GET, both under the API root
    (D-65). A redirect followed blindly carries the token to wherever it
    points. A token goes only to the instance that issued it (D-03).
15. **Keep the sign-in as it is**: the person's own public OAuth
    application, a loopback redirect, PKCE (D-66). Personal access
    tokens and the device flow are declined (D-101), and so is a shipped
    client id (D-100). A refresh token is spent once, under the
    cross-process lock (D-67).
16. **Hand-write the fields used in `internal/gitlab`** rather than
    import a GitLab or GraphQL client library, or another project's code
    (D-08). depguard refuses the known ones. Use GraphQL only where REST
    has no route, one literal per operation, sent from a function whose
    doc comment says why REST cannot do it (D-09).
17. **Record a verdict before you call an API operation or model a
    field**, in `testdata/api-coverage.tsv` or `testdata/api-fields.tsv`
    (D-10).
18. **Give the two halves of a reply different bytes** (D-77).
19. **Emit every error as `[class] message`.** `make classes` holds the
    `Class` constants, the `Classes` list and the classes the code emits
    to one set (D-74).
20. **Keep every released tool, output field and resource URI under its
    name.** `make schema-diff` fails on a rename unless a major release
    declares it in a `**Breaking:**` entry; adding is fine (D-78).
21. **Make every rule able to fail**: a test, a list derived from the
    code, and a floor on what the check read (D-86). "Found nothing" and
    "looked at nothing" print the same line.
22. **Commit to a branch, not `main`, and leave the push to the owner**;
    the owner pushes, tags and merges. Get the owner's go before you
    touch an OAuth application, write outside the live driver's scratch
    projects, add a scope, move a tool between kinds or toolsets, or
    reverse a decision.
23. **Check a belief about GitLab against GitLab's source, the OpenAPI
    snapshot or a live probe, not a reference page's prose** (D-12),
    because those pages are often wrong or silent on what this server
    depends on. Record a verified GitLab behavior in the comment at the
    line that depends on it, with the source link and the live step that
    checks it.

## Definition of done

`make check` passes. `make checklist` holds this list to its `check:`
prerequisites, in order:

```
fmt vet tidy lint cover vuln licenses secrets leaks pins classes
api-coverage api-fields schema-diff descriptions bodies smoke staleness
docs checklist changelog-links transcript live-cover outcomes
evals-check mcpb release server-json actionlint goreleaser-check parity
```

- On a pull request CI also runs `changelog`, and `schema-ack`, which
  needs a commit footer naming each changed item of the tool surface.
- New behavior has tests, and the schema diff has been read, resources
  and annotations included.
- `/simplify`, `/code-review medium` and `/security-review` have run. A
  fixed finding is one line in the commit body. A declined one goes in
  the PR body, or becomes a present-tense constraint comment at the line
  it protects. Findings go there, not into `docs/`.
- A change to sign-in, the quick-action guard, diff positions, a
  witness or an API response shape has had a `make live` run whose
  transcript was read (D-82).

## Traps

- **Green gates are not done.** Every fake in `internal/gapi/gitlabtest`
  is written from what we believe GitLab does; only `make live` tests it.
- **GitLab runs quick actions from API bodies**, whatever the flags say.
  A body input that skips the guard is a hole, not a style issue.
- **A write's 401 is `[forbidden]` only after a read.** GitLab answers
  401, not 403, for a merge the role does not allow, and a plain 401 for
  a malformed token. `internal/gapi` reads the account after a write's
  401 and answers `[forbidden]` only if that read works (D-104).
- **`[not_found]` also means the token cannot see it.** GitLab answers
  404 for both.
- **A forbidigo settings block that fails to load leaves forbidigo on
  its defaults**, still firing. Check the message text.
- **A test can redirect the config directory but not the OS keyring.**
  `TestMain` in `cmd/gitlab-mcp` substitutes it, because `logout`
  revokes at GitLab.
- **Supersede or deprecate a decision rather than delete it, and take a
  fresh ID rather than reuse one.** The next ID is on the file's
  `Next ID:` line.

## Writing

Plain and short: lead with the outcome, one idea per sentence, no
narration, no count a gate does not check, no version in prose. History
goes in commit messages. Follow the CHANGELOG rules in `CONTRIBUTING.md`
to the letter, because `release.yml` lifts the section verbatim into the
release notes. The release procedure is `docs/release.md` and nowhere
else.
