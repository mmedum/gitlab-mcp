# Security review — v4.1.1

Range: `v4.1.0` to the release commit, on `release/v4.1.1`. Reviewed on
2026-10-24. The range changes three descriptions in the Claude Desktop
bundle's manifest and the documents.

**Result: no finding.**

- **The bundle's descriptions** for `read_only`, `enable_ship` and
  `enable_destructive` say that Read-only cannot be combined with either
  switch. The server's behavior is unchanged: `config.Build` refuses the
  combination with `[invalid]`, so the server does not start, which fails
  closed.
- **Correction to the v4.1.0 review.** It said that `read_only` "still
  beats both switches". It does not: the server refuses the combination
  at startup rather than letting either win. The conclusion stands, since
  a refusal registers no tool at all.
- **Release checks run:** `make check`; `make vuln` at `v4.1.0` (no
  vulnerabilities); `schema-diff` (no change against
  v4.1.0); the release rehearsal.
