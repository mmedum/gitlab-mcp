# Security review — v2.1.0

Range: `v2.0.0` to the release commit, on `main`. Reviewed on
2026-10-01.

**Result: no open finding at confidence 8 or above.** One low finding,
in the link breaking of #28, fixed before the release (#30).

- **The eight features** (#20 to #26, #29): reviewed in
  `post-2.0.0.md`, each on its own branch before it merged; its claims
  were spot-checked against the code here and hold.
- **Breaking links in a question** (#28, fixed in #30): one low finding.
  A bare domain had only its last dot broken, so `evil.com.uk` left
  `evil.com` linked; a domain right before an `@` with no address after
  it was left whole; and a broken scheme left `//host`, which linkify-it
  links as a protocol-relative URL. Each mattered only to a client that
  linkifies the question as plain text: a code span is never linkified.
  Fixed: every dot of a bare domain and every `//` are broken, and a
  domain before an `@` is left whole only when linkify-it would read the
  whole as an email address (§18 row 105). Examined and holding: hidden
  characters are removed before matching; labels in any script, with
  combining marks, and punycode TLDs are broken; full-width dots and a
  mark after the TLD are not linked by linkify-it.
- **Questions from the new tools**: `delete_snippet` and
  `run_merge_request_pipeline` build their questions in `render` like
  every other, quoting and binding the title, every file name and both
  branches. No service builds question text itself.
- **The tidy after the features** (#27): no finding. `Once` beside a
  POST or `Repeatable` is refused unsent; the iid check moved to the
  schema's minimum, which the SDK enforces; the in-memory instance's
  changes are refactors.
