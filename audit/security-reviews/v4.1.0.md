# Security review — v4.1.0

Range: `v4.0.1` to the release commit, on `release/v4.1.0`. Reviewed on
2026-10-24. The range changes the Claude Desktop bundle's manifest, two
gates and documents; no server code.

**Result: no finding.**

- **The bundle's new settings** (`packaging/mcpb/manifest.json`):
  `enable_ship`, `enable_destructive`, `toolsets` and
  `write_namespaces`, each wired to its `GITLAB_MCP_` variable.
  - Both switches default to `false`, so a bundle install registers what
    an unconfigured server does: 66 tools, checked by starting the
    bundled binary with Desktop's substituted defaults. The `mcpb` gate
    refuses a switch whose default differs from the server's, compared as
    JSON (§18 row 130).
  - `read_only` still beats both switches; `TestGate` holds that in the
    server, and the bundle only passes the values through.
  - `write_namespaces` empty means unconfined, as for an unconfigured
    server; the field's description and the README say so. Nothing is
    wider than before.
  - An unknown toolset name is refused at startup by the existing parser.
- **`privacy_policies`** is a static URL in the manifest. The server
  never fetches it. The leak gate lists `about.gitlab.com` by exact host
  with its reason, not by pattern.
- **The README in the bundle** is the repository's public README, which
  the leak gate already scans.
- **The gates** read `config.Vars` and the committed manifest; they add
  no file or network access.
- **Release checks run:** `make check`; `make vuln` at `v4.0.1` (no
  vulnerabilities); `deps`, `schema-refetch` (both vendored schemas
  unchanged upstream) and `leaks-history`; `schema-diff` (no change
  against v4.0.1); the release rehearsal, whose bundle passes
  `mcpb validate` 2.1.2.
