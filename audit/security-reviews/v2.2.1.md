# Security review — v2.2.1

Range: `v2.2.0` to the release commit, on `main`. Reviewed on
2026-10-02.

**Result: no finding.** The range holds one production change and tests.

- **A repeated delete's 404** (#44, `internal/gapi/client.go`
  `repeatedDelete`, `internal/service/destructive.go` `deleted`). A
  DELETE answered 404 after an earlier attempt that may have landed is
  `[ambiguous_outcome]`, not `[not_found]`.
  - `resent` is set only through `mayHaveLanded`: a send error that left
    the process, or a 5xx. A 429 and a connection never made do not set
    it, so a refused delete that then finds nothing is still
    `[not_found]`. A GET's 404 is untouched.
  - The message names the call (`call.Name`, a fixed tool-side label)
    and nothing from the request or the answer, so no path, query or
    payload reaches the model or a log.
  - `deleted()` reports the item gone only when a read afterwards also
    finds nothing. An unconfirmed delete of something still there stays
    an error, so nothing is reported deleted that is not.
  - The class vocabulary is unchanged: `ambiguous_outcome` already
    existed and is documented in §4.5.
- **Tests only:** the client's dial-versus-reset retry rule, URL
  stripping at the very start of an error, and the leak gate on
  reserved-name lookalikes (`example.dk`, `corp.test.com`,
  `notexample.com`) and short base64. No fixture carries real data:
  every address is at a reserved domain.
- **Release checks run:** `schema-diff` (no change against v2.2.0),
  `deps`, `schema-refetch` (both vendored schemas unchanged upstream),
  `leaks-history` (150 commits, 5 tag messages, 1739 blobs, clean).
