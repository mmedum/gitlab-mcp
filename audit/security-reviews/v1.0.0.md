# Security review — v1.0.0

Range: the repository's first commit to the release commit. There is no
earlier tag, so the range is every phase. Reviewed on 2026-09-27.

**Result: no finding open.** Each phase was reviewed before it was
committed, and every finding is fixed and recorded in
`docs/architecture.md` §16a:

| Phase | Record |
|---|---|
| 0 | `v0.1.0.md` |
| 1 to 6 | `phase-1.md` to `phase-6.md` |

Two commits landed after the phase 6 review and were reviewed for this
release:

- **`706dea2`, `schema-ack` with a base from before the server.** It
  changes maintainer tooling only. A revision without `cmd/gitlab-mcp`
  counts as an empty surface, so every tool must be acknowledged. That
  makes the gate stricter, not weaker.
- **`8805a6c`, the first CI run's fixes.**
  - `credentials.Store.Save` stamps a store's saves strictly in order.
    It changes only `SavedAt`, never the token or where it is stored.
    Every caller holds the token source's mutex or runs once in
    `login`, so the new field has no race.
  - The in-memory instance bounds a label priority. That code is test
    only.
  - The bundle test closes its archive before repacking. Also test only.
  - CodeQL's alert on the leak gate's unanchored owner-link pattern was
    dismissed. The gate looks for links anywhere in text, so the pattern
    must match unanchored.

The release's live run found two wrong results, fixed on the release
branch (`docs/architecture.md` §16a, §18 rows 90 and 91):

- **`get_me`'s token expiry** is now the time of the read plus
  `expires_in`. The token is not read, logged or refreshed differently.
  The field only reports; refresh keeps its own expiry. The value now
  errs early.
- **`cancel_pipeline`'s outcome** is now decided from the status read
  first and GitLab's answer. It sends the same request as before, under
  the same Ship registration and write allow-list, and adds no input.
