# Security review — v1.0.0

Range: the whole tree at the release commit. There is no earlier tag,
so the review read everything rather than a diff. Reviewed on
2026-09-27.

**Result: two medium and eight low findings, all fixed before the tag.
No high finding.** Each is in `docs/architecture.md` §16a under "The 1.0
security review".

## How it was read

The tree was split five ways, and each part was reviewed on its own
against `CLAUDE.md`'s hard rules and the design in
`docs/architecture.md`:

| Part | What |
|---|---|
| Sign-in and secrets | `cmd/gitlab-mcp`, `auth`, `credentials`, `userconfig`, `fileperm`, `config`, `instance`, `app` |
| The REST client | `gapi` (not its fake), `gitlab`, `redact` |
| The write guards | `quickaction`, `scopes`, `server`, `tools`, and every writing path in `service` |
| Untrusted content | `render`, masking, the read paths in `service`, `model`, `diffpos`, resources, tool descriptions and server instructions |
| The release chain | workflows, `.goreleaser.yaml`, `Makefile`, `packaging/mcpb`, the gates release and publish run, module pins |

Only findings held at 80% confidence or more were reported. Each fix has
a test that fails without it.

## Findings

- **Medium: a confidential issue could be made public.**
  `update_issue {confidential: false}` was Write and unguarded, so an
  injected "it was confidential by mistake" could publish a
  vulnerability report. That transition now needs Ship.
- **Medium: a canceled tool call could lose the only valid token pair.**
  The refresh ran on the caller's context. A cancel that landed after
  GitLab rotated the pair dropped the new one, and the old one was
  already revoked. The refresh now runs on a context the caller cannot
  cancel.
- **Low: sign-in.**
  - A stored token under a profile that records no instance is withheld
    from the test instance.
  - `logout` holds the refresh lock.
- **Low: the REST client.** A create's over-size answer is
  `[ambiguous_outcome]`, not retryable.
- **Low: untrusted content.**
  - Artifacts lose terminal escapes before masking.
  - Unused reference definitions are dropped as hidden text.
  - A backtick in a fence's info string opens no fence.
  - The milestone title goes inside the boundary.
  - Snippet file names in an error are made plain.
- **Low: the release chain.** A manual registry publish refuses a
  prerelease.

## What was checked and holds

- **Sign-in:**
  - Loopback on `127.0.0.1:0`, `state` and PKCE from `crypto/rand`,
    S256 only; no redirect followed.
  - Token text never reaches an error.
  - Files 0600 or an owner-only DACL, profile names by pattern.
  - The refresh lock and re-read after `invalid_grant`.
- **The client:**
  - No redirect but a same-origin GET under the API root, once.
  - The token only on the same origin.
  - Every path segment escaped once; dot and control segments refused.
  - Page tokens bound to their query and carrying no URL.
  - A body cap after decompression.
  - POST never repeated.
  - Dry run refused before the token is fetched.
  - Logs carry no payload.
- **Write guards:**
  - Every Markdown body GitLab interprets passes the quick-action guard.
    Probes with CR, BOM, zero-width, fullwidth and indented lines agreed
    with GitLab's extractor.
  - Ship and Destructive are unregistered without their flags.
  - Every write resolves its project through the allow-list, the second
    project of a move or link included.
  - Rule 7 holds for commits, cherry-picks, reverts, rebases and tags.
  - Witnesses are required where §4.6 says.
- **Untrusted content:**
  - A 64-bit boundary per call.
  - Forged markers defused.
  - Job logs cleaned before masking and masked before cutting.
  - `structuredContent` carries only masked text.
  - Nothing that content references is fetched.
  - No description tells the model to act on content.
- **The release chain:**
  - No `${{ }}` in a `run:`.
  - No `pull_request_target`.
  - Actions pinned to full SHAs.
  - Write and OIDC permissions only on the release job, which needs a
    green CI.
  - The cosign identity is the exact workflow at the exact tag, verified
    before the registry reads the checksums.
  - The bundle packs a fixed list.
