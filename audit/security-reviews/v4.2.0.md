# Security review — v4.2.0

Range: `v4.1.4` to the release commit. Reviewed on 2026-11-01 with
`/security-review`, beside `/simplify` and `/code-review medium`. It
covers one change: every write that changes or removes something says
`destructiveHint: true`, and a new `Adding` kind carries the six writes
that only add.

**Result: no finding at confidence 8 or above.**

- **The hint is advisory.** It tells a client whether to ask first; it
  grants nothing. The MCP schema says a client should never decide on
  annotations from a server it does not trust. Twenty-nine writes now
  say `true`, which can only make a client ask more often.
- **Adding is gated exactly as Write is.** `Scope()` gives both the write
  scope, and `gate()` refuses both in read-only mode, so no tool moved
  out from under `GITLAB_MCP_READ_ONLY` or `GITLAB_MCP_WRITE_NAMESPACES`.
  `TestGate` lists an `Adding` tool beside the `Write` one.
- **No tool moved behind or out from behind a flag**, and no `confirm`
  was added or dropped. The tool list, every input and every output are
  unchanged; only the annotation differs.
- **The six on Adding start nothing.** A write that can start a
  pipeline, make one item hold another, mark to-dos done or resolve a
  thread stays on `Write`. `TestOnlyToolsThatAddSayTheyAreNotDestructive`
  names the six and fails on a hint left unset.
- **The kinds were renumbered.** `Adding` sits after `Write` in the
  `iota` list. No kind is stored, logged by number or sent anywhere, so
  the new numbers reach nothing outside the process.
- **Release checks run:** `make check`; `make vuln` at `v4.1.4` and at
  `HEAD` (no vulnerabilities); `deps` (7 direct dependencies),
  `schema-refetch` (both vendored schemas unchanged upstream) and
  `leaks-history` (268 commits, 16 tag messages, 2563 blobs, no leak);
  `schema-diff` (29 annotations, acknowledged); a live run against the
  scratch group, every call as expected, its transcript read; the
  release rehearsal.
