# Security review — v4.1.2

Range: `v4.0.1` to the release commit, on `release/v4.1.2`. Reviewed on
2026-10-24 with `/security-review`. It covers 4.1.0 and 4.1.1, whose
reviews were written by hand, and the gate changes since.

**Result: no finding at confidence 8 or above.**

- **The bundle's settings** (`packaging/mcpb/manifest.json`): the two
  switches default to `false` and the text fields to `""`, which
  `internal/config` reads as unset (`parseBool`, `parseToolsets`,
  `parseNamespaces`), so a default install registers what an
  unconfigured server does. A host that left `${user_config.x}`
  unsubstituted would fail closed: the parsers refuse the text and the
  server does not start. Read-only with either switch is refused at
  startup. `upload_dirs` keeps its refusal of the home folder and disk
  roots. The profile default moving from `default` to `""` selects the
  same profile.
- **No secret or development override** reaches the bundle: the gate
  refuses `config.DevVars()` and, since this range, every excluded
  setting, the refresh token among them, and any `env` on a platform
  override.
- **The leak gate's `about.gitlab.com` entry** matches that host
  exactly, after parsing the URL, so a lookalike or a `user@` prefix is
  not allowed.
- **The gate** builds its environment from the committed manifest only
  and calls `config.Load`, which neither writes nor reaches the network.
- **Release checks run:** `make check`; `make vuln` at `v4.1.1` (no
  vulnerabilities); `deps`, `schema-refetch` (both vendored schemas
  unchanged upstream) and `leaks-history`; `schema-diff` (no change
  against v4.1.1); the release rehearsal, whose bundle passes
  `mcpb validate` 2.1.2 and whose Linux binary registers the same 66
  tools with the bundle's defaults as with no settings.
