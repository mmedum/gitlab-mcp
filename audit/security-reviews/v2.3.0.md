# Security review — v2.3.0

Range: `v2.2.1` to the release commit, on `main`. Reviewed on
2026-10-08.

**Result: no finding at confidence 8 or above.** Three low findings,
recorded below, each resolved before the tag in `97c2a66` (§16a).

- **Where `upload_file` reads** (#51, `internal/localimage/localimage.go`
  `Read`, `within`, `openIn`): no finding.
  - `Read` refuses a relative path, any `..` element and an empty
    directory list before it touches the file system. `within` is
    lexical, so a path outside every allowed directory is `[blocked]`
    with nothing on disk looked at.
  - `openIn` opens the directory with `os.OpenRoot` and the file with
    `root.Lstat` and `root.OpenFile`, so `..` and links resolve inside
    the root. A link that leaves it, and every absolute link, is
    refused as escaping. The widest-first fallback moves to a narrower
    directory only on that refusal, and each try is a root on an
    allowed directory, so whatever opens is inside one.
  - `regular` refuses a link, a directory, a FIFO, a device and a
    socket on the `Lstat`. The open adds `O_NONBLOCK` where FIFOs exist
    (`open_unix.go`). `unchanged` holds the open file to the checked one
    with `os.SameFile`, so a swap in between is `Changed`, `[conflict]`.
    A link swapped in is followed by `os.Root` to another file, which
    `os.SameFile` refuses.
  - No trailing slash reaches `os.Root`: it is given `filepath.Rel` of
    the cleaned path, so the read does not depend on how `os.Root`
    treats one. Probed: `good.png/` reads `good.png`, `link.png/` is
    refused as a link, and `dirlink/o.png/` as escaping.
  - A hard link inside an allowed directory reads as the file it names.
    Making one needs write access to that directory, and the sniff
    still refuses what is not an image (§7.10).
- **What `upload_file` reads and sends** (`localimage.Read`, `name`;
  `internal/gapi/call.go` `Form.encode`): no finding.
  - A size over 10 MiB in the open file's `Stat` is refused before any
    read. Then 512 bytes are sniffed with `http.DetectContentType`, and
    anything but PNG, JPEG, GIF or WebP is refused without reading
    more. The refusal names no type. SVG sniffs as text, HTML or XML
    and is refused. The rest goes through `io.LimitReader` to one byte
    past the cap and is refused past it, so a file that grows while it
    is read is still bounded.
  - `name` keeps ASCII letters, digits, `.`, `-` and `_`, makes every
    other rune and every invalid byte `_`, drops leading dots, caps the
    stem at 100 and puts on the sniffed type's extension. Probed with
    `]`, `(`, `<img …>`, backticks, `#`, `@`, `~`, a line break, NUL
    and invalid UTF-8: none survive. `mime.FormatMediaType` writes the
    name as a bare token in `Content-Disposition`. No directory is
    sent.
- **Quick actions and Markdown** (rule 5): no finding. GitLab answers
  `![<name without extension>](/uploads/<secret>/<name>)` (§18 row
  113). It starts with `!`, and the name holds no line break, bracket,
  parenthesis, angle bracket, backtick or reference sigil (`#`, `!`,
  `@`, `~`, `%`, `$`, `&`, `^`). So it can neither run a quick action
  nor open or close a construct. The upload POST runs none
  (`scripts/gates bodies`, `lib/api/markdown_uploads.rb`). The
  Markdown reaches GitLab only in a body the model writes, which
  passes the guard like any other. `render.UploadWrite` shows it
  through `Ident` in a code span.
- **`GITLAB_MCP_UPLOAD_DIRS`** (`internal/config/config.go`
  `parseUploadDirs`, `tooWide`): one low finding, below.
  - The value splits as `PATH` does, unless the whole value is an
    existing absolute directory, which is then one entry. A relative
    entry, `~/…` included, a filesystem root (`/`, `//`, `C:\`, a
    share), and the home directory or one holding it fail startup.
    Home is compared after `userconfig.RealPath` on both sides, so a
    link to home or to its parent is caught. Probed on Linux: `/`,
    `//`, `~/x`, a relative entry, home, its parent and a link to
    either are refused, and a folder named `a:b` is kept whole.
  - The list reaches only `localimage.Read`: no log, `status` line or
    tool error names it. The startup refusal quotes the refused entries
    as written, to stderr, as `GITLAB_MCP_CONFIG_DIR`'s refusal does.
- **Low, the home check compares names** (confidence 6;
  `config.tooWide`). `userconfig.RealPath` keeps a name's case as
  written, and `filepath.Rel` compares bytes outside Windows. On a
  case-insensitive file system, macOS's default, `/users/<name>` is the
  home directory and passes startup; so does a name in another Unicode
  normalization. `upload_file` can then read every image under home,
  by paths spelled the same way. The check also runs once, by name,
  while `os.OpenRoot` resolves the name on every call, so a directory
  missing at startup can later be made a link to home by whoever can
  write its parent. Reasoned from the Go source; not run on macOS.
  Fix: compare identities. Refuse a directory for which `os.SameFile`
  holds against home or any of its ancestors, at startup and again on
  the opened root in `openIn`.
  - **Resolved:** `tooWide` now also compares each directory with home
    and every directory above it by `os.SameFile` at startup
    (`TestUploadDirsRefuseHomeInAnotherCase`, which runs where the disk
    ignores case: macOS and Windows CI; its failure was not shown on
    the Linux machine that wrote it). No per-call check in `openIn`: a
    later swap needs write access to this machine, outside the threat
    model.
- **Order, dry run and the question** (`internal/service/upload.go`
  `UploadFile`, `internal/render/ask.go` `AskUploadFile`,
  `internal/tools/ask.go`): two low findings, below.
  - `writeTarget` holds the project to the allow-list before anything
    on this machine is read. A refused project gets the same answer for
    an existing, a missing and a relative path
    (`TestUploadFileIsHeldToTheAllowList`).
  - A dry run reads the image and returns before it asks or sends.
    `prepare` refuses a write under a dry-run context all the same.
  - The question goes out only when the client declares form
    elicitation, and `GITLAB_MCP_REQUIRE_PROMPT` refuses as `[blocked]`
    otherwise. It shows the project, the name, type and size, who can
    open the link, the Maintainers' reach and the metadata, each value
    through `quoted`. It binds the SHA-256 of the bytes. The answering
    round reads the file again, so a file changed in between is
    `[blocked]`, and the bytes sent are the ones just hashed. Anything
    but an accept is refused in `personFor` before anything runs.
- **Low, no question means no second gate** (confidence 4;
  `service.UploadFile`, `tools.person.Ask`). The POST needs only read
  access to the project (§18 row 116). A client that declares no form
  elicitation gets no question. `upload_file` is Write, registered by
  default, and has no `confirm`, so §4.12's "the flags and `confirm`
  are the guard" does not hold for it. A planted comment can then have
  any image in the allowed directories uploaded to a public project its
  author maintains, who downloads it by id. §7.10 names the question as
  the guard against exactly this. Only `GITLAB_MCP_UPLOAD_DIRS`, which
  is opt-in, and `GITLAB_MCP_WRITE_NAMESPACES` stand. Fix, the
  maintainer's call: refuse `upload_file` when no question is possible
  unless the allow-list is set, or say in §4.12, `docs/security.md` and
  `docs/configuration.md` that without a question the directory and
  the allow-list are its only guards.
  - **Resolved, by the second fix:** the maintainer chose to allow the
    upload when no question is possible, unless
    `GITLAB_MCP_REQUIRE_PROMPT=true`. §4.12, `docs/security.md` and
    `docs/configuration.md` now say that the directories and the write
    allow-list are then its only guards, and advise either setting.
- **Low, two guards no test breaks** (confidence 3; rule 19;
  `render.AskUploadFile`, `localimage.openIn`). Removing the bytes'
  hash from the question's bind leaves every test green, and so does
  dropping the call to `unchanged` in `openIn`; `unchanged` is tested
  only on its own. Confirmed by mutation in a copy of the tree. Without
  the first, an image changed between the question and the answer,
  with the same name, type and size, goes out on the old accept. Fix: a
  `TestAskBinds` row for `AskUploadFile` with the same text and other
  bytes, and a hook between `Lstat` and the open that a test uses to
  swap the file and expect `Changed`.
  - **Resolved in part:** `TestAskBinds` has the row, and fails with the
    hash removed. The call to `unchanged` stays untested: a hook between
    `Lstat` and the open is a test-only back door, which the testing
    standard forbids; §16a records it beside the non-blocking open.
- **Errors and logs** (`service.imageRefused`, `localimage.failed`): no
  finding.
  - Each kind maps to a §6.5 class: `invalid`, `blocked`, `not_found`
    or `conflict`, and `unexpected` for a kind not worded. No message
    names a path, a directory or the list, or says what a refused file
    holds. `NotRegular` names the kind of node and `Unreadable` the
    system's reason, both only for a path inside an allowed directory.
    `failed` keeps only `PathError.Err`. Probed: no refusal's text
    carries the path.
  - The tool-call log line has the method, tool, outcome, duration and
    bucket, and gapi's has the fixed call name. Neither the form nor
    the answer is logged. `TestLogsNeverCarryThePayload` uploads a file
    whose directory and name carry the canary, checks that the 201 was
    logged, and finds no canary.
  - The result carries the name sent, the type, the size and GitLab's
    answer, never the directory.
- **Request bodies timed by progress** (`internal/gapi/client.go`
  `attempt`, `progress`): no finding.
  - Every payload, JSON or the form, is wrapped and given back its
    `ContentLength` and `GetBody`, which `http.NewRequestWithContext`
    sets on its own for a `*bytes.Reader`. v2.2.1 sent every JSON write
    with a `GetBody` already, so what can be replayed is unchanged.
  - Go 1.27.1 calls `GetBody` in three places. The HTTP/1 transport's
    `rewindBody`, for a POST only when the HTTP/2 pool had no
    connection or after a `nothingWrittenError` on a reused connection:
    no byte reached the socket. The HTTP/2 transport's
    `shouldRetryRequest`, only for a connection unusable before the
    stream opened, a GOAWAY whose last stream is below this one, or
    `REFUSED_STREAM`: streams RFC 9113 says the server did not process.
    The client's redirect loop, which builds the next hop before
    `CheckRedirect`. `ErrUseLastResponse` (`gapi.New`,
    `app.NewHTTPClient`) returns the 3xx with that hop unsent, and
    `followMove` refuses any redirect but a GET's. No POST is sent twice
    (rules 8 and 10). A dial failure after such a retry is `neverSent`
    and is retried, which holds for the same reason.
  - The clock restarts only when a `Read` takes bytes, and the payload
    is finite, so it cannot run forever. A send that stalls for the
    timeout is canceled, and a create so cut is `[ambiguous_outcome]`
    (`TestAWriteIsTimedByItsProgress`). An attempt with a body is now
    bounded by its pieces times the timeout rather than by the timeout:
    `docs/configuration.md` and the comment on
    `config.DefaultHTTPTimeout` still call `GITLAB_MCP_HTTP_TIMEOUT` the
    deadline for one attempt.
