# Security review — v2.4.0

Range: `v2.3.0` to the release commit, on `release/v2.4.0`. Reviewed on
2026-10-10.

**Result: no finding at confidence 8 or above.** One low finding, the
cost the maintainer chose with the mark change, recorded in §16a.

- **The interaction mark** (f88461f, `internal/tools/ask.go`
  `canAsk`, `interactionHint`; `register.go` `AsksEveryCall`;
  `tools.go` `register`): one low finding.
  - What changed is one `_meta` key in a `tools/list` answer, and only
    for a client that declares form elicitation. Registration, the Ship
    and Destructive flags, `confirm: true`, every witness, the
    quick-action guard and the server's question are untouched. Every
    tool that loses the mark asks the person itself before every write:
    the service calls `ask` on every path that reaches the write, after
    the last read. Every return before it writes nothing: a refusal, a
    dry run, or a target already in its end state (merged, approved,
    applied). Read for all twelve: `MergeMergeRequest`,
    `ApproveMergeRequest`, `ApplySuggestions`, `PlayJob`,
    `CreateRelease` and the seven deletes.
  - `run_pipeline` and `run_merge_request_pipeline` ask only on a
    protected ref and keep the mark, as do the seven Ship tools that
    never ask. Flipping either pipeline to `AsksEveryCall` fails
    `TestTheMarkIsDroppedOnlyWhereTheServerAlwaysAsks`, so a pipeline
    on an unprotected ref cannot quietly lose its only per-call
    prompt.
  - The mark is dropped from a copy. The server's own `*mcp.Tool` is
    listed to every session, and a change to it would strip the mark
    from a later client that cannot ask. The test lists one server as
    a client with form elicitation first, then with none and with URL
    elicitation only, on all three protocols, and fails when the
    middleware edits the original (mutation run, 2026-10-10).
  - `always` is built while the tools register, before the server
    serves, and only read afterwards; the suite passes under `-race`.
  - `canAsk` is the rule `personFor` already used: form, or an empty
    elicitation capability, which means form before 2025-11-25. A
    client that declares URL elicitation alone keeps the mark and gets
    no question, as before.
  - **Low: an accepting client now confirms these twelve writes
    alone.** Before, Claude Code showed its own prompt first for a
    marked tool, under any allow rule, and an `Elicitation` hook could
    answer only the second question. Now a Claude Code `Elicitation`
    hook that accepts makes such a write with no person asked
    (code.claude.com/docs/en/hooks, "Elicitation output": "The server
    gets your answer and no dialog appears", read 2026-10-10). So does
    any client that accepts an empty form by itself, as Codex and VS
    Code can (§4.12 item 2). A person
    must configure such a hook, and the registration flags still decide
    whether the tool exists. The maintainer chose this on 2026-10-09
    (§14); `docs/security.md` and the CHANGELOG say it.
  - **Known limit, not a finding:** from 2026-07-28 a client sends its
    capabilities with every request, and the Go SDK v1.8.0 reads the
    request's before the session's. A client can declare form
    elicitation to `tools/list` and none to `tools/call`, and get
    neither the mark nor a question. It gains nothing: a client that
    declares form elicitation can accept the question itself.
    `GITLAB_MCP_REQUIRE_PROMPT=true` refuses such a call (§18 row 120).
  - Headless Claude Code: a marked call was denied there
    (code.claude.com/docs/en/mcp, read 2026-10-10). With the mark
    dropped, a call an allow rule lets through reaches the server, which
    asks. Whether `claude -p` then declines or cancels the question,
    which is `[blocked]`, is owed to a live check before the tag. The
    code path for any answer but `accept` is the existing one, held by
    `TestOnlyAnAcceptConfirms`.
  - No new log line, error class or output field. The schema dump uses
    a client without elicitation, so the recorded surface keeps every
    mark, and `schema-diff` reads no change.
- **Go 1.27.2** (`efb7796`, `a78aea7`): no finding. `go.mod` moves the
  `go` directive from 1.27.1 to 1.27.2, which CI and `release.yml` read
  through `go-version-file`. `govulncheck` v1.8.0 finds no reachable
  advisory under 1.27.2, where it found ten under 1.27.1. Evidence row
  115 was read again against 1.27.2: the cited `os.Root` lines are
  unchanged, and the one `os.Root` advisory 1.27.2 fixes, GO-2026-6604
  (`Mkdir` and `MkdirAll` following a Windows junction), reaches no call
  `localimage` makes.
- **The v2.3.0 release record** (`106b00d`): no finding. It holds the
  public release run's id, hashes and gate results, and no account,
  path or token. The `leaks` gate passes on it.
- **Code review** (`/code-review high` over the uncommitted change,
  2026-10-10): two changes made before f88461f. `register` refuses
  `AsksEveryCall` on a tool that carries no mark, so `create_tag` and
  `upload_file`, which are Writes, no longer set it. The middleware is
  added only when some tool needs it. Not changed: a client that
  declares different capabilities to `tools/list` and `tools/call` is
  the known limit above (§18 row 120). `AsksEveryCall` is a claim
  about the service that no test drives path by path; it was read by
  hand for all twelve, as above. The headless check is owed, as above.
