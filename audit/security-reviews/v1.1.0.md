# Security review — v1.1.0

Range: `v1.0.0` to the release commit, on
`clear-label-milestone-fields`. Reviewed on 2026-09-27. Scope: the
`clear_*` inputs of `update_label` and `update_milestone`, the shared
`notBoth` and `clearing` helpers `update_issue` now uses too,
`LabelUpdate`'s `null` priority, and the live driver's steps for them.

**Result: no finding at confidence 8 or above.**

Examined and holding:

- **Order of checks.** The `clear_*` inputs are validated before any
  call. The write allow-list, the label's version, the refusal of a
  group's label and the milestone's `updated_at` all run before a body
  is built, as before.
- **Dry run.** Both tools return before the PUT. The preview is built
  from the same marshaling as the wire body, so it names `priority`
  exactly when `null` would be sent.
- **What reaches GitLab.** `ClearPriority` is never serialized itself;
  it makes `priority` `null` and changes no other field, and only when
  the label has a priority.
- **Quick actions.** The new inputs are booleans; no body input is
  added, and the descriptions stay routed as the bodies gate lists them.
- **Logs.** Nothing new is logged.
