# Security review — v4.1.3

Range: `v4.1.2` to the release commit, on `family-rules`. Reviewed on
2026-10-24 with `/security-review`, beside `/simplify` (one agent
covering the four angles) and `/code-review medium`. It covers pull
request 81 (bundle commands to staged programs, untitled refused fields
reported once, the profile rule held) and the family sweep.

**Result: no finding at confidence 8 or above.**

- **The refresh token** is read in one place, `Store.EnvToken`, through
  `config.Lookup`; trimming does not change which credential is used, and
  the token reaches no log, error or output. A nil `Env` means the
  process's environment everywhere, so `Resolve` and the store agree.
- **The status and doctor masker** reads `GITLAB_MCP_TEST_INSTANCE`
  through `config.Lookup` and masks the host as before; a scan now
  refuses any read of a server variable outside `internal/config` that
  does not go through `Lookup`, with a floor.
- **The bundle** cannot register Ship, Destructive or extra toolsets by
  default: the defaults diff, the base `args` of `[]` (now decoded, so a
  whitespace-only list is not misread), no `args` or `env` on an
  override, and env keys held to server variables with values of exactly
  `${user_config.x}`. Commands name staged programs under
  `${__dirname}/`, each platform its own file, never a document; a
  repeated key, case variants included, is refused.
- **Changed errors**: `ValidProfile` gives the rule in words and echoes
  the profile name as before; a profile name is not one of rule 3's
  payload kinds.
- **Release checks run:** `make check`; `make vuln` at `v4.1.2` (no
  vulnerabilities); `deps`, `schema-refetch` (both vendored schemas
  unchanged upstream) and `leaks-history` (254 commits, 14 tag messages,
  no leak); `schema-diff` (no change against v4.1.2); a live run against
  the scratch group, every call as expected; the release rehearsal.
